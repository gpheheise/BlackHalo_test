# BlackHalo Disclosures

The public record of vulnerabilities found by **BlackHalo**, the offensive-security platform of
**Lufthansa Industry Solutions**, created by Georg Ph. E. Heise.

A static site for GitHub Pages: no build step, no framework, no third-party requests except to
GitHub itself. Every disclosure links to its own research repository, and the site renders that
repository's `README.md` as the writeup.

## How it fits together

```
gpheheise/blackhalo                 ← this repository (the site)
├── index.html                      page shell
├── data/                           GENERATED by the private vault; don't edit by hand
│   ├── stats.json                  precomputed numbers for the overview (a few KB)
│   ├── embargo.json                redacted findings under embargo, one compact row each
│   ├── index/<year>.json           released disclosures, one compact row each, newest first
│   └── details/<year>/<date>.json  full records for one release day, loaded when a CVE is opened
├── assets/
│   ├── css/site.css
│   ├── js/app.js                   rendering, filters, routing, writeup reader (config at the top)
│   ├── js/cvss.js                  CVSS v3.1 calculator, shared with the validator
│   ├── js/vendor/                  marked 18.1.3, DOMPurify 3.4.17 (self-hosted)
│   ├── fonts/                      Geist + Geist Mono (self-hosted, SIL OFL)
│   └── img/                        logo, favicon, social preview
├── writeups/                       optional fallback writeups (CVE-ID.md)
├── templates/research-repo/        README + poc/ template for a new research repository
├── scripts/validate.mjs            data checks (runs in CI and in the vault before every push)
└── .github/workflows/validate.yml

gpheheise/blackhalo-vault (private) ← source of truth: every finding, withheld details included
gpheheise/CVE-2026-48210            ← one research repository per disclosure
├── README.md                       the writeup, rendered on the site
└── poc/                            the proof of concept
```

Opening a disclosure loads `https://raw.githubusercontent.com/<repo>/<branch>/<writeup>`, renders
the Markdown, and sanitises it with DOMPurify before it touches the page. Relative links and images
in the README are rewritten to GitHub, so screenshots in `img/` just work. Because the writeup is
fetched live, fixing a typo in the research repository updates the site without a redeploy.

If the repository is private, renamed or unreachable, the site falls back to
`writeups/<CVE-ID>.md` in this repository, then to the summary with a link to GitHub.

Every disclosure has its own URL: `https://<user>.github.io/blackhalo/#cve-2026-48210`.

## Built for volume

BlackHalo can report 50–100 findings a day per run, and several runs in parallel. The site is laid
out for about 300 a day: roughly 27,000 findings under embargo at any time and 100,000 released a year.

- The page first loads `stats.json` and `embargo.json` (together about 330 KB gzipped at that
  volume). Everything above the fold comes from those two files.
- Released disclosures load by year, newest first, in the background. Search covers the whole
  archive once the older years are in.
- Full records and writeups load only when someone opens a CVE.
- Only a page of cards is ever in the document (24 on the clock board, 48 in the archive, with
  "Show more"), and the one-second countdown only updates the cards that are rendered.

Measured with 127,000 synthetic findings in headless Chrome:

| | Desktop | Phone (CPU slowed 4×) |
|---|---|---|
| Page ready, clock and stats drawn | 0.6 s | 1.5 s |
| Whole 100,000-entry archive searchable | 1.6 s | 3.5 s |
| Search across the archive | ≤ 0.1 s | ≤ 0.3 s |
| Open a CVE (details fetched) | 0.06 s | 0.16 s |
| DOM size | 1,700 nodes | 1,700 nodes |

## Disclosure clock (findings under embargo)

New findings appear on the site the day the vendor is notified, with only a tracking ID
(`BH-2026-0021`), the vulnerability class, the CVSS score and a 90-day countdown. Vendor, product,
CVE and writeup are withheld until the clock runs out, then published automatically, fixed or not.
Each countdown shifts from green (90 days) to red (final day).

The clock section has:

- **Five figures**: under embargo, reported in the last 24 h (with a 14-day sparkline), releasing
  within 24 h and 7 days, patched under embargo, and the next full disclosure.
- **Full-disclosure forecast**: releases per day for the next 90 days, coloured by how close they
  are, with monthly totals. Click a day to list exactly those findings.
- **The board**: tabs for *Next to disclose*, *Newest*, *Recently fixed* and *Highest CVSS*;
  filters for severity, class and status (awaiting acknowledgement, acknowledged, fixed, extended,
  paused, CVE assigned); search by ID, class or CWE; card or compact list view.
- **Latest activity**: newly reported, fixed and released findings as they happen.

The withheld details **never live in this repository**: GitHub Pages serves every file and git
keeps every version, so hiding them in the browser would hide nothing. They live in the private
`blackhalo-vault` repository, whose hourly workflow writes the files in `data/` here. CI rejects
any field in `embargo.json` outside the allowed list, and the vault runs the same check before it
pushes.

Adding findings (CSV/JSON import, an inbox folder, bulk updates via export → Excel → import) and
steering single findings (acknowledged, fixed, extend, hold, release now, CVE assigned) all happen
in the vault. See its README.

Each embargoed finding has its own link, `#bh-2026-0021`. After release, the same link opens the CVE.

## Adding older CVEs

CVEs that never went through the clock go into the vault too, so the site has one source. Put them
in a CSV with a `cve` column and a past `date` (the publication date), plus the usual `reported`,
`type`, `vector`, `vendor`, `product`, `title`, `summary`, `repo`, `poc`, then `bh import` and
publish (the vault has `templates/published-cves-template.csv`). With `reported`, `acknowledged`
and `fixed` dates, the CVE gets a disclosure timeline and counts in the time-to-fix figures; without
`reported` it is listed without a timeline.

For the research repository, create a public repository from `templates/research-repo/` (for
example `gpheheise/CVE-2026-50001`) and write the README and PoC there.

| Field | Notes |
|---|---|
| `repo` | `owner/name` of the research repository. Leave empty for a finding without one. |
| `branch`, `writeup` | Default to `main` and `README.md`. Use `writeup: docs/advisory.md` for a different file. |
| `poc`, `pocPath` | `poc: yes` links `https://github.com/<repo>/tree/<branch>/<pocPath>`. |
| `pocUrl` | Optional full https URL when the PoC lives elsewhere (one shared tools repo, say). |
| `type` | Weakness class used for filters and the class chart. |
| `vector` | CVSS 3.1 vector; score and severity are calculated from it. |

Several disclosures can share one repository (a monorepo of writeups). Point each at its own file
with `writeup`.

## Run locally

```bash
npm run validate          # check the generated data in data/
npm run validate:repos    # also confirm every linked writeup is publicly reachable
npm run serve             # http://localhost:8000. Opening index.html from disk won't load the data.
```

## Deploy on GitHub Pages

1. Push this repository as `gpheheise/blackhalo` (or change `SITE` at the top of `assets/js/app.js`).
2. **Settings → Pages → Deploy from a branch → `main` / root.**
3. If the repository name isn't `blackhalo`, update the `/blackhalo/` paths in `404.html` and the
   `og:image` URL in `index.html`.

## Before going public

- Delete the **demo findings** in the vault (fictional vendors) and the three demo files in
  `writeups/`. The vault's first publish replaces everything in `data/`.
- Remove the "Demo dataset" notice in `index.html` (`id="demo-notice"`).
- Put your real contact and PGP key in `SECURITY.md`.

## Security and privacy

- Content Security Policy as a meta tag (GitHub Pages can't set headers): scripts and styles from
  this origin only, network access limited to this origin and `raw.githubusercontent.com`.
- No inline scripts or event handlers. All dataset values are escaped, and writeups are sanitised.
- Fonts and libraries are self-hosted, so visitors' browsers never contact Google Fonts or a CDN.
